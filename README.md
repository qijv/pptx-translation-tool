# PPT 翻译替换工具

[English](README.en.md) · [在线使用](https://ppt.naodong.store/) · [MIT 许可证](LICENSE)

一个轻量的浏览器端 PPTX 文本翻译辅助工具。文件只在用户本机浏览器中解析，不上传服务器。

工作流程：上传 PPTX → 复制带编号与格式标记的提示词到你选择的 AI → 粘贴译文 → 导出新 PPTX。项目不内置翻译模型，不需要 OpenAI API Key。

## 功能

- 上传 `.pptx` 并提取幻灯片文本。
- 按页内 ID 输出文本，例如 `[1-1]`、`[2-1]`。
- 复制给外部 AI 时自动附带提示词。
- 支持全部复制、按页数分批复制、按行数分批复制。
- 粘贴译文后批量写回 PPTX，并导出新文件。
- 译文内容排版提供图片示例：默认保留原格式，或选择智能排版。智能排版按每个文本框的尺寸、边距、继承字号、字体与段落间距，在本机浏览器测量译文；能放下时保留字号，放不下才逐步缩小，最低为原字号的 70%，且原本大于等于 12 磅的文字不缩到 12 磅以下，原本更小的文字不再缩小。结果写入明确字号，不依赖 Office 的自动缩放。达到下限仍放不下，或竖排、分栏、艺术字、表格等暂不支持可靠估算时，提示对应编号；特殊排版保留原设置。不扩大文本框，不截断正文，不保证跨字体和 PowerPoint/WPS 显示完全一致。设置作用于含译文的整个文本框（包括保留的原文），刷新或上传新文件恢复默认，不持久化。
- 支持亮色 / 暗色模式。

## 本地开发

```bash
npm ci
npm run dev
```

## 构建

```bash
npm run build
```

构建产物输出到 `dist/`，可直接部署为静态站点。

需要 Node.js 22.12 或更高版本；也可使用满足 Vite 7 要求的 Node.js 20.19+。运行 `npm test` 检查文本解析、格式标记和导出回归。

## 隐私与自部署

- PPT 文件、提取正文和译文在浏览器本地处理。你手动复制到外部 AI 的内容（提示词包含文件名）受该服务的隐私政策约束。
- 自部署默认关闭访问统计，不生成统计访客标识，也不请求原站统计服务。
- 可选统计配置见 [.env.example](.env.example)。仅配置自己运营的服务；所有 `VITE_*` 配置都会公开进入浏览器产物，不能存放任何秘密。修改后需重新构建。
- 启用统计时，客户端会发送站点标识、页面地址（含查询参数）、来源页、浏览器信息及保存在 localStorage 的访客标识；不发送 PPT 正文和译文。托管服务还可能记录请求 IP。原在线站点启用了访问统计。
- 在线站点与本仓库分别发布；更新 GitHub 代码不会自动更新在线站点。

## 注意

- 当前仅支持现代 `.pptx` 文件，不支持旧版 `.ppt`。
- 按段落生成 ID，同一段中的富文本片段不会再拆成多个翻译条目。相邻的相同样式片段会合并。
- 样式差异使用 `<s1>…</s1>` 标记，手动换行使用 `<br1/>` 标记；译文可调整样式范围的位置，导出后保留对应原样式，标记不会显示在 PPT 中。
- 可修正常见的标记空格、全角括号、转义括号或单侧尖括号缺失；缺失整对标记、重复、嵌套或未知标记会阻止导出。动态字段必须保留原值。
- 新 ID 按段落编号，旧版本按片段编号的译文不能直接用于新版本，需重新提取、翻译。
- 每个编号的译文必须在同一行。无编号续行、额外说明和不属于当前 PPT 的编号会提示并阻止导出，不自动拼进正文；续行需手动合回对应编号行。支持编号中的全角方括号、空格及常见破折号变体。
- 保留样式不代表自动解决排版溢出，较长译文仍应在 PowerPoint 中检查。
- 外部工具兼容性需要实测：Google 翻译网页在中文转英文的小样本中删除了 `<s1>` 标记，此类结果会被拦截，不能直接保留富文本样式。建议使用能遵守附带提示词并保留标记的 AI；提示词无法保证所有工具都会保留标记。
- 解析、翻译匹配和导出都在浏览器本地完成。
